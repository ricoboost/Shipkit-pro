# Database Issues

Troubleshoot common database problems with Prisma, PostgreSQL, and connection issues.

---

## Connection Errors

### Cannot Connect to Database

**Error:** `P1001: Can't reach database server`

**Diagnosis:**

```bash
# Test connection string
node -e "
const { PrismaClient } = require('@prisma/client');
const prisma = new PrismaClient();
prisma.\$connect().then(() => console.log('Connected!')).catch(console.error);
"
```

**Common causes and fixes:**

1. **Wrong connection string:**

```bash
# Format
DATABASE_URL="postgresql://USER:PASSWORD@HOST:PORT/DATABASE?schema=public"

# Example
DATABASE_URL="postgresql://postgres:password@localhost:5432/myapp?schema=public"
```

2. **Database not running:**

```bash
# Check PostgreSQL status
pg_isready -h localhost -p 5432

# Start PostgreSQL (macOS)
brew services start postgresql

# Start PostgreSQL (Linux)
sudo systemctl start postgresql
```

3. **Firewall blocking connection:**

```bash
# For cloud databases, check IP whitelist
# Neon: Dashboard → Settings → IP Allow
# Supabase: Settings → Database → Connection Pooling
```

---

### Connection Timeout

**Error:** `P1002: The database server was reached but timed out`

**Solutions:**

1. Add connection timeout:

```bash
DATABASE_URL="postgresql://user:pass@host:5432/db?connect_timeout=10"
```

2. Use connection pooling for serverless:

```bash
# Pooled connection (for app)
DATABASE_URL="postgresql://user:pass@pooler.host:6543/db?pgbouncer=true"

# Direct connection (for migrations)
DIRECT_DATABASE_URL="postgresql://user:pass@host:5432/db"
```

3. Configure in Prisma schema:

```prisma
datasource db {
  provider  = "postgresql"
  url       = env("DATABASE_URL")
  directUrl = env("DIRECT_DATABASE_URL")
}
```

---

### Too Many Connections

**Error:** `P2024: Timed out fetching a new connection from the pool`

**Solutions:**

1. Limit Prisma connection pool:

```bash
DATABASE_URL="postgresql://user:pass@host:5432/db?connection_limit=5"
```

2. Use singleton pattern:

```typescript
// src/lib/prisma.ts
import { PrismaClient } from '@prisma/client';

const globalForPrisma = globalThis as unknown as {
  prisma: PrismaClient | undefined;
};

export const prisma =
  globalForPrisma.prisma ??
  new PrismaClient({
    log: process.env.NODE_ENV === 'development' ? ['query', 'error', 'warn'] : ['error'],
  });

if (process.env.NODE_ENV !== 'production') {
  globalForPrisma.prisma = prisma;
}
```

3. Close connections properly:

```typescript
// For scripts or API routes
try {
  // Your code
} finally {
  await prisma.$disconnect();
}
```

## Prisma Migration Issues

### Migration Failed

**Error:** `P3006: Migration failed to apply`

**Diagnosis:**

```bash
# Check migration status
npx prisma migrate status

# View migration history
npx prisma migrate resolve --rolled-back MIGRATION_NAME
```

**Reset and try again (development only):**

```bash
# Warning: This deletes all data!
npx prisma migrate reset
```

---

### Schema Drift

**Error:** `P3005: The database schema is not in sync with the migration history`

**Solutions:**

1. For development - reset database:

```bash
npx prisma migrate reset
```

2. For production - baseline migration:

```bash
# Mark existing migrations as applied
npx prisma migrate resolve --applied MIGRATION_NAME
```

3. Or introspect current state:

```bash
npx prisma db pull
npx prisma generate
```

---

### Migration Stuck

**Error:** Migration hanging or timeout

**Solutions:**

1. Check for locks:

```sql
-- Run in database client
SELECT * FROM pg_locks WHERE granted = false;

-- Kill blocking queries
SELECT pg_terminate_backend(pid) FROM pg_stat_activity
WHERE state = 'idle in transaction';
```

2. Increase timeout:

```bash
# In connection string
DATABASE_URL="postgresql://...?connect_timeout=60&statement_timeout=60000"
```

## Schema Issues

### Model Not Found

**Error:** `Property 'modelName' does not exist on type 'PrismaClient'`

**Solution:** Regenerate Prisma client:

```bash
npx prisma generate
```

---

### Field Type Mismatch

**Error:** `P2009: Invalid value for field`

**Check your schema types:**

```prisma
model User {
  id        String   @id @default(cuid())  // String, not Int
  email     String   @unique
  credits   Int      @default(0)           // Int, not String
  createdAt DateTime @default(now())
}
```

**Ensure data matches:**

```typescript
// ❌ Wrong
await prisma.user.create({
  data: {
    credits: "100", // String instead of Int
  },
});

// ✅ Correct
await prisma.user.create({
  data: {
    credits: 100, // Int
  },
});
```

---

### Unique Constraint Violation

**Error:** `P2002: Unique constraint failed on the fields: ('email')`

**Handle gracefully:**

```typescript
try {
  await prisma.user.create({
    data: { email: 'test@example.com' },
  });
} catch (error) {
  if (error.code === 'P2002') {
    // Handle duplicate entry
    throw new Error('User with this email already exists');
  }
  throw error;
}
```

**Or use upsert:**

```typescript
await prisma.user.upsert({
  where: { email: 'test@example.com' },
  update: { name: 'Updated Name' },
  create: { email: 'test@example.com', name: 'New User' },
});
```

## Query Issues

### Query Returning Null

**Check your queries:**

```typescript
// findUnique returns null if not found
const user = await prisma.user.findUnique({
  where: { id: 'non-existent' },
});
// user === null

// Use findUniqueOrThrow to throw error instead
const user = await prisma.user.findUniqueOrThrow({
  where: { id: 'non-existent' },
});
// Throws P2025 if not found
```

---

### N+1 Query Problem

**Symptoms:** Slow queries, too many database calls

**Solution:** Use includes:

```typescript
// ❌ N+1 problem
const users = await prisma.user.findMany();
for (const user of users) {
  const posts = await prisma.post.findMany({
    where: { authorId: user.id },
  });
}

// ✅ Optimized with include
const users = await prisma.user.findMany({
  include: {
    posts: true,
  },
});
```

---

### Slow Queries

**Enable query logging:**

```typescript
const prisma = new PrismaClient({
  log: [
    { level: 'query', emit: 'event' },
    { level: 'error', emit: 'stdout' },
  ],
});

prisma.$on('query', (e) => {
  console.log('Query: ' + e.query);
  console.log('Duration: ' + e.duration + 'ms');
});
```

**Add indexes:**

```prisma
model User {
  id    String @id @default(cuid())
  email String @unique

  // Add index for frequently queried fields
  @@index([createdAt])
}

model Post {
  id       String @id @default(cuid())
  authorId String

  @@index([authorId]) // Index for foreign keys
}
```

## Data Recovery

### Accidental Deletion

**If you have backups:**

```bash
# Restore from backup
pg_restore -d myapp backup.dump
```

**Soft deletes pattern:**

```prisma
model User {
  id        String    @id @default(cuid())
  deletedAt DateTime?
}
```

```typescript
// Soft delete
await prisma.user.update({
  where: { id: userId },
  data: { deletedAt: new Date() },
});

// Query only active users
const activeUsers = await prisma.user.findMany({
  where: { deletedAt: null },
});
```

## Common Prisma Error Codes

| Code | Description | Solution |
|------|-------------|----------|
| P1001 | Can't reach database | Check connection string, firewall |
| P1002 | Database timeout | Increase timeout, check server |
| P2002 | Unique constraint violation | Handle duplicate, use upsert |
| P2003 | Foreign key constraint | Ensure related record exists |
| P2025 | Record not found | Handle null case |
| P3005 | Schema drift | Reset or resolve migrations |
