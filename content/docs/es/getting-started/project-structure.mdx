# Estructura del Proyecto

ShipKit sigue una estructura bien organizada basada en las convenciones de Next.js App Router.

## Vista General de Directorios

```
shipkit/
├── content/
│   └── docs/           # Archivos MDX de documentación
├── prisma/
│   └── schema.prisma   # Esquema de base de datos
├── public/             # Recursos estáticos
├── src/
│   ├── app/            # Páginas de Next.js App Router
│   ├── components/     # Componentes de React
│   ├── config/         # Archivos de configuración
│   ├── hooks/          # Hooks personalizados de React
│   ├── lib/            # Bibliotecas principales y utilidades
│   └── middleware.ts   # Middleware de Next.js
├── .env.example        # Plantilla de variables de entorno
├── next.config.ts      # Configuración de Next.js
└── package.json        # Dependencias
```

## Conceptos Clave

### Grupos de Rutas

Los grupos de rutas `(groupName)` organizan rutas sin afectar la URL:

- `(marketing)` - Páginas públicas en `/`, `/pricing`, `/blog`
- `(auth)` - Páginas de autenticación en `/login`, `/register`
- `(dashboard)` - Páginas de usuario en `/dashboard`, `/settings`
- `(admin)` - Páginas de administración en `/admin`

### Abstracción de Proveedores

Cada característica principal usa una interfaz unificada:

```typescript
// lib/auth/index.ts exporta interfaz unificada
export const auth = getAuthProvider(); // Devuelve proveedor configurado

// El uso es el mismo independientemente del proveedor
const session = await auth.getSession();
```

### Tipado Seguro

Todas las APIs usan Zod para validación y oRPC para endpoints con tipado seguro:

```typescript
// Llamadas API completamente tipadas
const result = await rpc.users.getProfile.query();
```
