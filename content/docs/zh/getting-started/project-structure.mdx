# 项目结构

ShipKit遵循基于Next.js App Router约定的良好组织结构。

## 目录概览

```
shipkit/
├── content/
│   └── docs/           # 文档MDX文件
├── prisma/
│   └── schema.prisma   # 数据库模式
├── public/             # 静态资源
├── src/
│   ├── app/            # Next.js App Router页面
│   ├── components/     # React组件
│   ├── config/         # 配置文件
│   ├── hooks/          # 自定义React Hooks
│   ├── lib/            # 核心库和工具
│   └── middleware.ts   # Next.js中间件
├── .env.example        # 环境变量模板
├── next.config.ts      # Next.js配置

```

## 关键概念

### 路由组

路由组 `(groupName)` 在不影响URL的情况下组织路由：

- `(marketing)` - `/`、`/pricing`、`/blog`的公共页面
- `(auth)` - `/login`、`/register`的身份验证页面
- `(dashboard)` - `/dashboard`、`/settings`的用户页面
- `(admin)` - `/admin`的管理页面

### 提供商抽象

每个主要功能使用统一接口：

```typescript
// lib/auth/index.ts导出统一接口
export const auth = getAuthProvider(); // 返回配置的提供商

// 无论提供商如何，使用方式相同
const session = await auth.getSession();
```

### 类型安全

所有API使用Zod进行验证，使用oRPC实现类型安全的端点：

```typescript
// 完全类型化的API调用
const result = await rpc.users.getProfile.query();
```
