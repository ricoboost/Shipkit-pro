# Projektstruktur

ShipKit folgt einer gut organisierten Struktur basierend auf Next.js App Router Konventionen.

## Verzeichnisübersicht

```
shipkit/
├── content/
│   └── docs/           # Dokumentations-MDX-Dateien
├── prisma/
│   └── schema.prisma   # Datenbankschema
├── public/             # Statische Assets
├── src/
│   ├── app/            # Next.js App Router Seiten
│   ├── components/     # React-Komponenten
│   ├── config/         # Konfigurationsdateien
│   ├── hooks/          # Benutzerdefinierte React-Hooks
│   ├── lib/            # Kernbibliotheken und Hilfsprogramme
│   └── middleware.ts   # Next.js Middleware
├── .env.example        # Umgebungsvariablen-Vorlage
├── next.config.ts      # Next.js Konfiguration
└── package.json        # Abhängigkeiten
```

## Schlüsselkonzepte

### Routengruppen

Routengruppen `(groupName)` organisieren Routen ohne die URL zu beeinflussen:

- `(marketing)` - Öffentliche Seiten unter `/`, `/pricing`, `/blog`
- `(auth)` - Authentifizierungsseiten unter `/login`, `/register`
- `(dashboard)` - Benutzerseiten unter `/dashboard`, `/settings`
- `(admin)` - Admin-Seiten unter `/admin`

### Anbieterabstraktion

Jede Hauptfunktion verwendet eine einheitliche Schnittstelle:

```typescript
// lib/auth/index.ts exportiert einheitliche Schnittstelle
export const auth = getAuthProvider(); // Gibt konfigurierten Anbieter zurück

// Die Verwendung ist unabhängig vom Anbieter gleich
const session = await auth.getSession();
```

### Typsicherheit

Alle APIs verwenden Zod zur Validierung und oRPC für typsichere Endpoints:

```typescript
// Vollständig typisierte API-Aufrufe
const result = await rpc.users.getProfile.query();
```
