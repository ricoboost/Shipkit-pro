# Project Structure

ShipKit follows a well-organized structure based on Next.js App Router conventions.

## Directory Overview

```
shipkit/
├── content/
│   └── docs/           # Documentation MDX files
├── prisma/

├── public/             # Static assets
├── src/
│   ├── app/            # Next.js App Router pages
│   ├── components/     # React components
│   ├── config/         # Configuration files
│   ├── hooks/          # Custom React hooks
│   ├── lib/            # Core libraries and utilities
│   └── middleware.ts   # Next.js middleware
├── .env.example        # Environment variables template
```

## Key Concepts

### Route Groups

Route groups `(groupName)` organize routes without affecting the URL:

- `(marketing)` - Public pages at `/`, `/pricing`, `/blog`
- `(auth)` - Auth pages at `/login`, `/register`
- `(dashboard)` - User pages at `/dashboard`, `/settings`
- `(admin)` - Admin pages at `/admin`

### Provider Abstraction

Each major feature uses a unified interface:

```typescript
// lib/auth/index.ts exports unified interface
export const auth = getAuthProvider(); // Returns configured provider

// Usage is the same regardless of provider
const session = await auth.getSession();
```

### Type Safety

All APIs use Zod for validation and oRPC for type-safe endpoints:

```typescript
// Fully typed API calls
const result = await rpc.users.getProfile.query();
```
