# Estrutura do Projeto

O ShipKit segue uma estrutura bem organizada baseada nas convenções do Next.js App Router.

## Visão Geral dos Diretórios

```
shipkit/
├── content/
│   └── docs/           # Arquivos MDX de documentação
├── prisma/
│   └── schema.prisma   # Schema do banco de dados
├── public/             # Recursos estáticos
├── src/
│   ├── app/            # Páginas do Next.js App Router
│   ├── components/     # Componentes React
│   ├── config/         # Arquivos de configuração
│   ├── hooks/          # Hooks personalizados do React
│   ├── lib/            # Bibliotecas principais e utilitários
│   └── middleware.ts   # Middleware do Next.js
├── .env.example        # Template de variáveis de ambiente
├── next.config.ts      # Configuração do Next.js

```

## Conceitos-Chave

### Grupos de Rotas

Grupos de rotas `(groupName)` organizam rotas sem afetar a URL:

- `(marketing)` - Páginas públicas em `/`, `/pricing`, `/blog`
- `(auth)` - Páginas de autenticação em `/login`, `/register`
- `(dashboard)` - Páginas de usuário em `/dashboard`, `/settings`
- `(admin)` - Páginas administrativas em `/admin`

### Abstração de Provedores

Cada recurso principal usa uma interface unificada:

```typescript
// lib/auth/index.ts exporta interface unificada
export const auth = getAuthProvider(); // Retorna provedor configurado

// O uso é o mesmo independentemente do provedor
const session = await auth.getSession();
```

### Segurança de Tipos

Todas as APIs usam Zod para validação e oRPC para endpoints com tipagem segura:

```typescript
// Chamadas de API completamente tipadas
const result = await rpc.users.getProfile.query();
```
